# Supabase setup / データベースの設定

## 1. テーブルを作る

1. Supabase の左メニューから **SQL Editor** を開く
2. **New query** をクリック
3. `schema.sql` の中身を**全部コピーして貼り付け**
4. 右下の **Run** を押す

「Success. No rows returned」と出れば完了です。何度実行しても問題ありません。

## 2. 管理者アカウントを作る

注文一覧を見るためのログイン用アカウントです。

1. 左メニューの **Authentication** → **Users**
2. **Add user** → **Create new user**
3. メールアドレスとパスワードを入力
4. **Auto Confirm User** に必ずチェックを入れる
5. **Create user**

このメールとパスワードで管理画面にログインします。

## セキュリティの考え方

サイトに埋め込むキー（anon key）は公開される前提のものです。したがって
**誰でもこのデータベースに到達できます。** そのうえで安全を保つために、
アクセス権を次のように限定しています。

| 誰が | できること | できないこと |
|---|---|---|
| 一般の訪問者 | 注文を作る／支払いを報告する | **注文を読む・書き換える・消す** |
| ログインしたatelierR | すべて読む／状態を変える | 消す（削除は許可していません） |

とくに重要な点：

- **注文を読み取る権限が一般には一切ありません。** 他人の注文はもちろん、
  自分の注文も読めません。お客様が自分の注文を見られるのは、ブラウザ内に
  控えが残っているからです
- **「支払い済み」の状態で注文が作られることはありません。** データベース側の
  ルールで、新規注文は必ず未払い状態から始まります
- **お客様は注文の状態を書き換えられません。** 「支払いました」という申告は
  `payment_reports` に別途記録されるだけで、注文そのものには触れません。
  支払いの確定は、atelierR が PayNow を確認してから手動で行います

## テーブル

**`orders`** — 注文1件につき1行

氏名・住所・商品・金額は、注文時点の内容をそのまま固めて保存します。あとから
商品の値段を変えても、過去の注文の金額は変わりません。

**`payment_reports`** — 「支払いました」の申告

お客様の申告は事実ではなく申告なので、注文とは別の場所に記録します。
